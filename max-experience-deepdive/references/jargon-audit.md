# 术语审计

## 为什么必做

深挖出来的「为什么」如果用术语来讲，外行听到第一个不懂的词时，后面的推理就断了。断了之后，再深的思考对方也接收不到。

但「懂不懂」没有统一答案，**取决于面试官是谁**。同一个词，对 HR 要翻译，对同行直接说；对同行还翻译，反而显得你不专业。所以审计前必须先知道面试官的身份（SKILL.md 的 Step 0）。

## 第一步：根据面试官身份推断他的知识背景

| 面试官身份 | 大概率懂 | 可能懂，需要轻带一下 | 大概率不懂 | 最关心什么 |
|---|---|---|---|---|
| **HR / 招聘** | 日常词、通用职场词 | DAU、转化率这类常见指标 | 所有行业术语和技术术语 | 你的角色、协作方式、软技能、结果 |
| **跨部门业务负责人** | 业务指标、成本、ROI | 相邻领域的术语 | 底层技术细节 | 成本、结果，为什么值得做 |
| **同岗位同行**（比如产品面产品） | 本岗位的通用方法和指标 | 你所在细分领域特有的概念 | 你们公司内部的叫法、内部系统名 | 你的判断和取舍，方法能不能迁移 |
| **技术负责人**（比如算法面产品） | 技术术语，如提示词、SFT、基模 | 产品和业务侧的指标 | 你们业务特有的产品概念 | 判断依据是否严谨，有没有理解技术边界 |
| **高管 / 终面** | 行业大方向、商业逻辑 | 主流技术概念的名字 | 实现细节 | 这件事对业务有多大价值，你的视野 |

**两条通用原则：**
- **公司内部的叫法谁都不懂**：内部系统名、项目代号、团队简称，对任何外部面试官都要翻译。
- **拿不准就往下降一档**：判断不了对方懂不懂时，按「可能懂」处理，用一句话轻带，既不冒犯内行，也不会让外行掉队。

## 第二步：逐个审计

1. 把经历描述里的名词**逐个**拎出来，包括产品名、行业术语、技术术语和职场黑话。
2. 对照第一步的推断，逐个判断**这位面试官**能不能懂：
   - ✅ 他肯定懂：直接用，不解释
   - ⚠️ 他可能懂：用「术语 + 也就是 + 一句话」轻带一下
   - ❌ 他不懂：换成他生活里或他的行业里见过的东西
3. 对 ❌ 和 ⚠️ 的词选择处理方式：

| 处理 | 什么时候用 | 例子 |
|---|---|---|
| **删** | 这个词不承载推理 | 「帮助算法迭代优化」→「告诉工程师该改哪儿」 |
| **换** | 这个词承载推理，但外行听不懂 | 「粒子」→「照片上飘的星星、花瓣」 |
| **保留并翻译** | 需要体现专业度 | 「做 SFT，也就是专门拿正确例子给 AI 补课」 |

4. 改写完后，再把全文扫一遍：确认 ❌ 的词不再出现在版本一里，✅ 的词也没有被多余地解释。

## 同一个词，对不同面试官怎么说

以「我们决定先重跑几轮，再决定要不要做 SFT」为例：

| 面试官 | 说法 |
|---|---|
| HR | 我们先让 AI 把同样的图多做几次，确认它是真的不会，再决定要不要花大成本给它专门补课 |
| 业务负责人 | 先重跑几轮确认问题是稳定出现的，再决定要不要做 SFT，也就是花几周准备数据、重新训练模型。这样能避免为偶发问题投入大成本 |
| 算法负责人 | 生成有随机性，所以我们先多跑几轮看问题是否稳定复现，再决定要不要上 SFT |

## 翻译技巧

- **锚在生活经验上**：相框、剪纸、说明书、投篮、补课。
- **抽象的词用例子替代**：「质感受损」→「脸被磨糊、发灰，看起来很假」。
- **讲清成本差异**：外行不懂技术，但懂「便宜 / 贵」「快 / 慢」。把几种方案按成本从低到高排开，比解释原理更有效。
- **只翻译到推理需要的程度**：不用解释 SFT 的原理，只要讲清「它很贵，要准备几百上千个例子」就够了。

## 常见术语翻译参考

### AI / 算法

| 术语 | 通俗说法 |
|---|---|
| 提示词 / Prompt | 给 AI 的指令，相当于说明书 |
| 基模 / 基座模型 | 底层的 AI 模型；「换基模」就是换一个更强的 AI |
| SFT / 微调 | 专门拿大量正确例子给 AI 补课 |
| 评测 / 评测集 | 检查 AI 做得好不好 / 一套固定的考题 |
| 生成随机性 | 同样的输入，AI 每次给的结果不完全一样，像投篮 |
| badcase | 出问题的例子 |
| 幻觉 | AI 一本正经地瞎编 |
| 召回 / 准确率 | 该找的找到了多少 / 找到的里面有多少是对的 |

### 互联网产品

| 术语 | 通俗说法 |
|---|---|
| DAU | 每天有多少人在用 |
| 留存 | 用过的人，过几天还回来用的比例 |
| 转化率 | 看到的人里，有多少真的去做了（买、注册、点击） |
| 漏斗 | 用户一步步往下走，每一步都有人流失 |
| 埋点 | 在 App 里记录用户点了什么 |
| A/B 实验 | 一半用户看旧版、一半看新版，比较哪个效果好 |
| 灰度 | 先给一小部分用户上线，没问题再全量 |
| 需求评审 | 大家坐下来确认这个功能要不要做、怎么做 |

### 职场黑话（一般直接删）

| 黑话 | 处理 |
|---|---|
| 赋能、抓手、闭环、打通、沉淀、对齐、颗粒度、链路 | 删掉，直接说具体做了什么 |
| 参与搭建、协助推进 | 换成具体分工：「标准是我定的」「报告是我写的」 |
| 帮助优化迭代 | 换成具体结果：「告诉他们该改哪里，最后 X 个问题解决了」 |

## 自检

把版本一念给一个和这位面试官背景相同的人听，问他：
1. 「这个功能或项目是干嘛的？」
2. 「他为什么做了那个关键选择？」

两个问题他都能用自己的话答出来，才算通过。
